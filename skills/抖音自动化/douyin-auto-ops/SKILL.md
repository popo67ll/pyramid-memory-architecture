### 技术流程

1. **进入高清发布页**(v1.33 更新):
   - 无论当前在哪个页面,第一步直接 `page.goto('https://creator.douyin.com/creator-micro/content/upload')` 导航到上传页
   - **⚠️ 铁律:不再依赖 DOM 查找「高清发布」按钮,直接导航即可**
2. **页面确认**(兜底导航):
   - 检查 URL 是否已在 `/content/upload`,如不在则强制 navigate 到上传页
3. **上传视频文件**:通过 `input[type="file"]` 的 `uploadFile()` 方法注入(使用 fileInputs[1] 视频专用)
3. **填写标题**:**跳过**(主人要求不填,避免与文案重复)
4. **填写描述**:在 `contenteditable` 编辑器中用 `execCommand('delete')` + `execCommand('insertText')` 一次性注入纯描述
5. **添加话题标签**:CDP `Input.insertText` 逐个输入每个话题 → 等弹窗出现 → CDP `Input.dispatchKeyEvent` 发送 `ArrowDown` + `Enter` 选择推荐话题 → 输入空格分隔(v1.29/v1.30 稳定版)
6. **添加 POI 定位**:DOM 检测扩展类型 → 自动切换为"位置" → `keyboard.type()` 搜索 → `.semi-portal` 精确匹配
7. **点击发布**:找到 "发布" 按钮,拟人化点击

### ⚠️ 发布功能关键技术点(v1.30 话题输入稳定版)

1. **混合策略输入(核心 v1.29/v1.30)**:
   - **描述**:`execCommand('delete')` + `execCommand('insertText')` 一次性注入**纯描述**(不带话题)
   - **话题**:CDP `Input.insertText` 逐个输入 `#话题名` → **等 2-3 秒**弹窗出现 → CDP `Input.dispatchKeyEvent` 发送 `ArrowDown` + `Enter` 选择推荐话题 → 输入空格分隔
   - **为什么改用 CDP**:原 `page.keyboard.type()` 在锁屏/长时间操作后可能丢失输入或焦点异常。CDP 协议直接发送底层输入事件,不依赖浏览器焦点,更稳定可靠。
   - **v1.23 焦点修复**:话题输入前用 `window.getSelection()` + `document.createRange()` 将光标精准定位到描述文本末尾,再输入话题
   - 示例流程:execCommand 注入描述 → 光标移到末尾 → CDP insertText `#南阳嗨舞` → 等弹窗 → CDP ArrowDown+Enter → 空格 → `#南阳嗨舞工作室` → ...

2. **文件上传(v1.27 修复)**:
   - 页面有两个 `input[type="file"]`:[0] 接受图片,[1] 接受视频
   - 必须使用 **fileInputs[1]**(accept="video/mp4,video/*"),否则视频上传失败

2. **位置(POI)输入(v1.19 DOM 检测)**:
   - **类型切换**:遍历 `.semi-select` 找包含"游戏手柄"/"位置"的元素 → 点击 → 等 2.5-3 秒 → 在 `.semi-portal` 中选"位置"
   - **输入框点击**:找 `.semi-select-selection-placeholder` 包含"输入地理位置" → 向上找 `.semi-select` 父元素点击(不写死坐标)
   - **搜索关键词**:`page.keyboard.type('锦湖电脑数码城', { delay: 50 })`(抖音实际 POI 名)
   - **必须用 `keyboard.type`**,不能用 JS 的 `input.value = xxx`
   - **选择结果**:等 3-4 秒后在 `.semi-portal` / `.semi-popover` 中找包含关键词的第一个结果项点击(主人确认第一个就是正确位置)
   - 回退方案:弹出层未找到时,键盘 `ArrowDown` + `Enter`

## 自动回复评论 + 私信(v66.0 混合策略)

### 📋 评论回复流程

1. **进入评论管理**:`https://creator.douyin.com/creator-micro/interactive/comment`
2. **点击「全部」选项卡**:确保显示全部评论(包括陌生人评论)
3. **检测视频卡片**:只处理最新 1 条视频的评论(v66 保守策略)
4. **DOM 精准解析评论**:
   - 找到所有「删除」按钮 → 向上遍历找包含 1 个删除+1 个回复的最小容器
   - TreeWalker 提取文本 → 解析用户名/内容/时间/嵌套回复标记
   - 过滤:我们的回复(零宽标记+关键词)、UI 元素、表情评论、重复评论
5. **逐条回复 + 刷新页面**(v43 方案):
   - 每回复 1 条后刷新页面重新收集评论,防止重复回复和漏回复
   - 每轮最多回复 5 条(MAX_REPLIES_PER_RUN)
   - 连续失败 2 次则暂停本轮回复(CONSECUTIVE_FAILURE_LIMIT)
6. **回复点击**:
   - 在 DOM 中精准匹配目标评论 → 找到对应的「回复」按钮 → 滚动居中 → dispatchEvent 点击
   - 等待嵌套回复面板出现(输入框在回复按钮附近 300px 内,父级包含「取消+发送」)
   - page.evaluate 直接注入文本 + 触发 input/compositionend 事件 → dispatchEvent 点击发送

### 📋 评论回复关键技术点(v66.0)

- **DOM 精准定位**:不用坐标猜位置,全部用 DOM 特征检测(「删除」按钮 → 最小容器 → TreeWalker 解析 → 回复按钮匹配)
- **缓存去重**:`/tmp/douyin_comments.json`,用 `${用户名}|${评论内容前30字}` 作为唯一键,最多保留 500 条
- **发送验证**:发送后检查「发送成功」toast / 嵌套面板已关闭 / 回复文本出现在页面上,三重验证防止「假发送」
- **验证码处理**:检测到验证码弹窗后暂停,轮询等待主人操作(最多 5 分钟),完成后自动重发

#### 2026-05-26 | 自动发布 v1.36 - 位置选择精准修复 ✅
- **现象**:位置输入框显示"锦湖电脑数码城"但有红色错误边框，DOM 验证 value 仍是 placeholder"输入地理位置"，位置值未正确绑定。
- **根因**:搜索结果弹窗有多个 `.semi-portal` 同时存在（搜索结果弹窗 + 类别选择器弹窗），原代码 `document.querySelector('.semi-portal')` 匹配到了错误的弹窗；且 `[class*="option"]` 选择器匹配到了包含多个结果的外层容器，而非单个可点击结果项。
- **修复方案**:v1.36 ①通过 `portal.textContent.includes(keyword)` 精准定位包含关键词的搜索结果弹窗，排除类别弹窗；②收集所有匹配元素后按面积排序，选面积最小的（最精确的单个结果项），避免点到容器；③新增 DOM 选择失败后的键盘回退机制(ArrowDown+Enter)。
- **核心教训**:抖音页面同时存在多个弹出层时，必须通过内容特征精准定位目标弹窗；点击选择结果时要区分容器和单个结果项（选面积最小的）。

#### 2026-05-21 | 自动回复 v75.0 - 修复时间正则漏匹配(纯昨天/小时前/天前)✅
- **现象**:陌生人私信有1条(用户名 `X^exo※`,消息"你好,具体位置在那里啊,怎么收费"),但脚本120秒轮询提取到0条,误判为无新私信。
- **根因**:私信提取正则 `timeMatch` 只支持 `14:59/刚刚/昨天14:59/5分钟前`,不支持纯`昨天`、`2小时前`、`3天前` 等格式,导致时间匹配失败后整条消息被跳过。评论时间正则 `timePattern` 同样不支持纯`昨天`/`X小时前`/`X天前`。
- **修复方案**:v75.0 1私信提取正则新增 `昨天|\d+小时前|\d+天前`;2评论时间正则改为 `昨天(\s*\d{2}:\d{2})?`(时间部分可选),新增 `\d+\s*小时前|\d+\s*天前`;3修复后陌生人私信从120秒提取0条 → 10秒成功提取1条并自动回复。
- **核心教训**:时间格式要覆盖所有可能的展示格式(纯日期、相对时间),正则设计时要用可选分组而非强制完整匹配。
